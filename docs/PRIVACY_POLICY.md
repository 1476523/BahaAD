# BahaAD 隱私權說明

BahaAD 是在您自己電腦上執行的下載工具。您追蹤／下載的番劇、動畫瘋帳號、密碼、Cookie、
下載的檔案與下載路徑，全部只留在您自己的電腦上。除了下面明確列出的項目，程式**不會**
把您的任何資料送出您的電腦。

本文件的適用範圍：BahaAD 程式本身，以及專案維護者提供的伺服器（為了提高可用性，目前有
一台「主要伺服器」與一台「備用伺服器」，兩者提供相同的服務、彼此同步資料，程式會先連
主要伺服器、連不上時自動改連備用伺服器；本文件說的「維護者伺服器」同時包含兩者）。

關閉後立即停止該項的所有回報，不會「關了還偷偷送」。

## 二、錯誤自動回報

程式發生錯誤時，會回報以下**固定欄位**——不多不少，這份清單本身就是完整範圍：

| 欄位 | 內容 | 說明 |
|---|---|---|
| 錯誤代碼 | 內建代碼表裡的一個代碼 | 代表發生錯誤的操作類型，不是原始例外訊息或程式堆疊 |
| 操作類型 | 例如「下載影片」「解析番劇頁面」「套用更新」 | 用來判斷問題出在哪個功能區塊 |
| 網路量測值 | 延遲、下載速率 | 用來判斷是不是網路狀況造成的問題 |
| 連線狀態分類 | 逾時／斷線／DNS 失敗等固定分類 | 不含實際連線對象的位址 |
| 檔案完整性比對結果 | SHA-256 是否相符 | 只有「相符／不相符」的結果，不會回報檔案內容本身 |
| 路徑資訊 | 相對於程式安裝目錄或下載目錄的**相對路徑** ＋ 磁碟機代號／剩餘空間 | 只有在出錯的路徑確實位於安裝目錄或下載目錄底下時才回報這一項，且只送相對部分；**只要無法確定，就整組不回報**，從根本上避免送出含使用者名稱的絕對路徑 |
| 動畫瘋身分 | `會員` / `遊客` / `未知` 三選一 | 用來判斷付費番劇下載失敗是登入狀態失效還是本來就用遊客身分；不含帳號、Cookie |
| 例外類型名稱 | 程式的例外類別名，例如 `FileNotFoundError`、`ConnectionError` | 只是 Python 內建／程式自訂的類別「名字」，**不是**例外訊息文字，本身不含任何您的資料 |
| 錯誤發生的模組 | 程式碼裡的模組名稱，例如 `bahaad.app_shell` | 告訴我們錯誤發生在哪一段程式，是程式碼結構的名字，不含任何您的資料 |

**不會**回報：帳號密碼、Cookie、您追蹤／下載的番劇清單內容、檔案內容本身、完整的
例外堆疊或原始錯誤訊息文字、含有使用者名稱的原始檔案路徑。完整訊息與堆疊只會寫進
您自己電腦上的日誌，不外傳。

回報的觸發範圍是「**任何未預期的錯誤**」——只要程式記錄到帶有例外的錯誤（含未捕捉的
例外），就會送出上面這一組固定欄位。這樣維護者才能在問題擴大前主動得知並處置。收到的
回報會彙整到維護者**私人**的問題追蹤工具（不公開）裡，方便歸類與追蹤同一個問題出現的次數。

「錯誤自動回報」目前若是關閉狀態，每次程式更新時會跳一次提醒說明它對排查問題的重要性；
這只是提醒，選擇繼續關閉完全不影響任何功能的可用性。

## 三、即時匿名使用統計

「即時統計」彙總所有 BahaAD 使用者的整體使用情況（下載量、訂閱／收藏數、使用與在線
人數、番劇觀看次數），顯示在隱私權說明浮層、BahaAD 排行榜與番劇頁上。

### 匿名啟動識別碼

- BahaAD **第一次啟動時**會產生一組 **16 字元的隨機識別碼**（大小寫英文、數字、`-`、
  `_`），加密後存在您電腦的 `%LOCALAPPDATA%\BahaAD` 資料夾。
- 它**只產生一次**：程式更新、重新下載安裝都不會換；「完全重置」也不會清掉它。**只有
  您手動刪除整個 `%LOCALAPPDATA%\BahaAD` 資料夾**，下次啟動才會產生一組新的。
- 它是一串**隨機字元**，不含、也無法反推出您的任何個人資訊（不是硬體序號、不是帳號、
  跟您的 GitHub 身分無關）。用途只有一個：讓伺服器在計算「使用人數」時能去重，不會
  把同一台電腦重複算成很多人。
- 關掉「即時統計」→ 立刻停止所有回報與心跳，這組識別碼**不再送出**（但仍留在您電腦上，
  重新打開就繼續用同一組）。

### 回報什麼

| 項目 | 內容 | 說明 |
|---|---|---|
| 匿名啟動識別碼 | 上述那串隨機字元 | 計算人數時去重用 |
| 總下載次數 | 每成功下載一集 +1（只有數字增量） | 不含番劇名、集數、檔案 |
| 訂閱／收藏狀態 | 「這台電腦目前有沒有訂閱／收藏某部番劇」＋番劇的**站方公開名稱** | 只有 on／off 狀態，統計「幾個人訂閱這部」；新番快訊的「追蹤」也算在收藏數裡 |
| 番劇觀看／看完次數 | 開始播放 +1、播到 80% +1（只有數字增量）＋番劇名 | |
| 目前狀態旗標 | 「有沒有排程下載」「有沒有開公開模式」兩個布林值 | 計算「實際使用人數」用 |
| 每分鐘心跳 | 「還在執行」＋「公開模式現在有沒有人在用」＋「正在看哪部番劇」 | 計算「當前在線人數／正在收看人數」；公開模式閒置超過 10 分鐘就不算在線 |

**不會**回報：帳號密碼、Cookie、您完整的訂閱／下載清單、檔案、下載路徑、
您的 GitHub 身分、任何可以指向「您是誰」的資料。番劇名稱用的是動畫瘋站上本來就公開的
節目名稱。

### 送不出去時

伺服器可能因維護而暫時無法連線。程式會先試主要伺服器、不行再試備用伺服器；兩者都連不上
時，回報會**暫存在您電腦上**（合併成增量，例如暫存期間下載 5 次就記一次 +5），之後按「每
3 分鐘（前 10 次）→ 每 1 小時（再 10 次）→ 之後每 3 小時」的節奏重試補送。心跳類（在線／
正在收看）不暫存——過期就沒有意義。

### 「所有使用者已回報錯誤次數」

設定頁「匿名使用統計」區會顯示「所有使用者已回報次數」——這是伺服器彙總的、所有
**開啟錯誤自動回報**的使用者到目前為止送出過幾筆的總數。它只是一個總數字，不含任何
錯誤內容。

## 四、GitHub 帳號綁定（可選）

BahaAD 的「同帳號多 IP 防護」與「star 提醒」功能需要您登入 GitHub 帳號。**不連結
GitHub 帳號完全不影響任何下載／排程功能。**

- 我們只查詢您是否已 star 本專案這一項狀態，不讀取您帳號的其他資訊。
- 授權採標準 OAuth 流程，BahaAD 全程不經手您的 GitHub 帳號密碼。程式本機只持有一組
  由伺服器核發、不透明、可隨時撤銷的權杖（token），加密保存在您自己的電腦上；程式
  從來拿不到您真正的 GitHub access token（那組權杖加密後只存在維護者伺服器，僅用於查詢
  star 狀態）。
- 連結後，伺服器會記下您的 **GitHub 帳號名稱**、是否已 star，以及連線時的 **IP 位址**。
  「同帳號多 IP 防護」靠 IP 位址判斷是否有帳號共享情形，**用途僅限於此**，不做其他用途。
  即時心跳所帶的 IP 紀錄只保留約一天；若偵測到同一帳號在短時間內出現多個 IP，這筆異常
  （帳號名稱與 IP）會記到維護者私人的問題追蹤工具，供維護者確認。
- 您可以隨時在設定頁按「中斷連結」：伺服器會**刪除**該登入階段（連同加密保存的授權權杖）；若這個 GitHub 帳號沒有其他連結中的裝置，也會一併刪除心跳 IP 紀錄與 star 狀態快取。star 名單（stargazers）是 GitHub 上本來就公開的資訊，不會因此刪除。

## 五、番劇資料補充與公開資訊

BahaAD 會讀取一些公開的網頁資訊來補充功能：

- 動畫瘋官方公告、GNN 新番文章、新番授權情報頁（新番快訊、公告解析用）。
- **其他公開的動畫資料來源**：補充簡介，以及動畫瘋本身沒有的「製作／配音／音樂」欄位，
  並在判定番劇完結前多做一道確認。程式每小時（最多）向該來源抓幾個公開的季度總覽頁面。
- 第一次啟動時，若電腦上沒有 ffmpeg，會從公開的下載來源取得一份放進自己的資料夾。

這些都是**單純的網頁 GET 請求**，**不會送出您的任何資料**——不帶 Cookie、不帶帳號、
不帶動畫瘋的登入資訊、沒有任何識別參數。抓回來的內容存在您自己電腦上。

## 六、每日簽到（可選，預設關閉）

設定頁的「每日簽到」開啟後，BahaAD 會每天在您設定的時間，用您**已登入的動畫瘋帳號**直接
向巴哈姆特站方送出簽到（及選擇性的領取雙倍巴幣）請求，並讀取您的巴幣餘額來確認有入帳。

- 這整個過程只發生在**您的電腦與巴哈姆特站方之間**，**不經過維護者伺服器**，簽到結果
  與巴幣餘額也**不會**被回報到任何地方（只會寫在您自己電腦的日誌、設定頁，以及您自己設定
  的 Telegram／Discord 通知裡）。
- 它使用的是您自己的登入資訊（以 Windows DPAPI 加密存在您的電腦上）；登入失效時不會自己
  重新登入，只會顯示登入失效提醒。
- 這是替您操作您自己的帳號，是否開啟、風險由您自行判斷（見 README 的「使用須知」）。

## 七、訂閱者 Discord/Telegram 通知（可選）

這是**另一群人**的資料——不是您（BahaAD 擁有者）自己的使用資料，而是您選擇開啟「公開
模式」並完成安裝實例綁定後，用「Discord 登入」或「Telegram 登入」自助登入這台 BahaAD
網站、收藏番劇並接收更新通知的**訂閱者**。跟上面各節完全獨立、完全不同的資料，也跟即時
統計的「匿名啟動識別碼」機制無關。

這項功能預設不會發送任何訊息，必須先在「公開模式」下由您開啟並完成綁定，且訂閱者要
**先主動**在網站上點選登入才會產生資料。

### 登入時經手什麼資料

| 項目 | 內容 | 存放位置 |
|---|---|---|
| Discord 登入 | 走 Discord 標準 OAuth2（只取得帳號 ID／使用者名稱，不取得密碼、不取得帳號其他資訊；額外請求「安裝到您的帳號」授權，用來嘗試讓 Bot 能主動私訊通知，不會取得您伺服器上的任何資料），交握全程經由官方中繼伺服器代為進行 | 中繼不保存訂閱者身分，只在登入當下驗證後轉交給您這台 BahaAD；**身分與收藏清單存在您自己這台電腦的 `bahaad.db`，中繼不存收藏內容** |
| Telegram 登入 | 走 Telegram 官方 Login Widget（網頁內嵌登入按鈕，交握全程經由官方中繼伺服器頁面代為進行，只取得帳號 ID／顯示名稱，不取得密碼） | 中繼不保存訂閱者身分，只在登入當下驗證後轉交給您這台 BahaAD；**身分與收藏清單同樣只存在您這台電腦** |
| 登入後的訂閱者身分 | Discord/Telegram 的帳號 ID、顯示名稱 | 只存在您這台電腦的 `bahaad.db`，中繼完全不保存 |

**不會**回報：訂閱者的密碼、Discord/Telegram 帳號的其他個人資訊、訂閱者所在裝置的
其他識別資訊。登入過程中，中繼伺服器與託管環境會因網路連線本身看到訂閱者的 IP 位址，
登入相關的安全事件（例如驗證失敗）可能連同 IP 位址記入伺服器日誌，保存約 30 天。

### 安裝實例綁定時，中繼伺服器保存什麼

您在「通知中心」按下綁定後，中繼伺服器會保存這台安裝實例的：**安裝識別碼**、您設定的
**公開網域**（回呼網址，用來把登入結果交還給您這台電腦）、以及一把用來簽章的**共用密鑰**
（加密保存）。這些只用於讓中繼辨認並回呼您的安裝實例；您可以隨時重新綁定，或關閉公開
模式使這項功能停用。

### 資料如何流動

訂閱者在網站點選登入 → 中繼代為完成 Discord OAuth 交握／Telegram Login Widget 驗證
→ 把驗證好的帳號 ID 用簽章交還給**您這台 BahaAD** → 您這台電腦本地建立訂閱者身分與
登入 session。番劇更新時，是您這台電腦主動請中繼代為發送通知——**官方 Bot／OAuth
應用程式的真實憑證只存在中繼伺服器，不會散布到任何一台自架的 BahaAD**。

### 關閉/移除

- 訂閱者可隨時在網站上登出，或取消個別番劇的收藏。登入有閒置自動登出（預設 60 分鐘），
  登出時畫面會提示。
- 您（BahaAD 擁有者）關閉「公開模式」或未設定「域名設定」時，這整項功能立即停用，
  訂閱者無法再登入或收到通知。

### 播放時的技術性防護記錄（登入者專屬）

已登入的訂閱者（或您本人）在瀏覽器內建播放器觀看番劇時，播放進度只存在**您自己的
瀏覽器**（`localStorage`，只有這個瀏覽器看得到，不會傳給任何伺服器）。為了防止爬蟲
等自動化工具濫用遠端播放功能，伺服器這端會在**記憶體**裡暫時記錄「這個登入身分
（帳號 ID）＋這一集」是否已通過防護判斷——這筆記錄只存在記憶體、不寫進 `bahaad.db`，
程式重新啟動就會清空；未登入的訪客不會有這筆記錄。

## 八、官方內容與意見回饋

程式會定期（約每 10 分鐘）向維護者伺服器取得官方提供的圖文內容清單，並把其中的圖片或影片快取在
**您自己的電腦上**，之後都從本機提供。這個過程：

- **不會送出任何識別資訊**，也**不會**統計內容被顯示或被點擊的次數。
- 這些內容只會出現在**公開模式下訪客看到的頁面**（例如番劇列表中的卡片、番劇頁播放前的圖片或影片），
  擁有者自己登入時不會看到。
- 點擊內容時，由訪客自己的瀏覽器直接前往對應的網站，不經過維護者伺服器，也不會回報點擊。

畫面上提供**意見回報**表單，只有您**主動送出**時才會傳送：您選擇的類別（固定幾種之一）、您自行填寫
的說明（最多 500 字，請不要填入個人資料）、相關的番劇編號與內容編號。伺服器**不記錄 IP 位址**，
也不需要登入；收到的回報會彙整到維護者私人的問題追蹤工具，用來處理內容問題。

## 九、維護者伺服器上保存的資料與期間

| 資料 | 內容 | 保存 |
|---|---|---|
| 錯誤回報 | 第二節的固定欄位 | 保存供維護者排查問題；不含可指向個人的內容 |
| 統計 | 匿名啟動識別碼、各番劇的訂閱／收藏狀態、觀看／看完累計、目前狀態旗標 | 累計資料持續保存；「正在收看」的即時紀錄約一天後清除 |
| GitHub 連結 | 帳號名稱、star 狀態、（加密的）授權權杖、連線 IP | 連結期間保存；心跳 IP 約一天；中斷連結即作廢 |
| 通知中繼 | 安裝識別碼、公開網域、（加密的）共用密鑰；登入用的一次性驗證碼與狀態 | 綁定期間保存；一次性驗證碼與登入狀態數分鐘到一天內清除 |
| 意見回報 | 類別、說明、番劇編號、內容編號（第八節），不含 IP | 保存供維護者處理；不含可指向個人的欄位 |
| 伺服器日誌 | 登入、安全事件等運作紀錄（內容會先遮蔽密鑰類資訊，部分事件含連線 IP） | 約 30 天後自動清除 |

主要伺服器與備用伺服器會互相同步上述資料，兩者的保存規則相同。伺服器的託管商與內容傳遞
網路（CDN）依其運作也會看到連線的 IP 位址，那是它們自己的紀錄，不在維護者的控制範圍內。

## 資料如何被使用

回報的資料（錯誤回報與即時統計）只用於排查程式錯誤、改善穩定性、以及呈現整體使用
規模的統計，儲存在專案維護者自行管理的伺服器上。不會與您的 GitHub 帳號身分做交叉
比對，也不會把「匿名啟動識別碼」跟任何其他身分關聯，除非未來有明確需要並另外告知。
不會出售、出租或提供給第三方。

## 這份清單以後會不會擴大？

不會隨意擴大。如果之後真的需要新增欄位，會更新這份文件並在程式更新時說明，不會用
「或是更多的資訊」這種開放式的方式蒐集。

## 同意方式

- 首次啟動時會有清楚顯眼的畫面列出「錯誤自動回報」的欄位內容，並附上本文件的連結。
- 「錯誤自動回報」與「即時統計」都預設開啟、各自獨立，可在設定頁的「匿名使用統計」
  區分別關閉。
- 關閉後立即停止該項的回報，不會「關閉了但還是偷偷送」。

## 刪除與查詢

您可以自行或請維護者刪除伺服器上與您有關的資料：

| 想刪除什麼 | 怎麼做 |
|---|---|
| 統計資料（匿名啟動識別碼名下的使用者端紀錄、各番劇訂閱／收藏狀態、正在收看紀錄） | 設定頁「匿名使用統計」→「刪除伺服器上的統計資料」（預設會一併關閉即時統計，不然下一輪回報會重新建立紀錄） |
| GitHub 連結資料（登入階段與授權權杖、心跳 IP、star 狀態快取） | 設定頁「GitHub 帳號連結」→「中斷連結」 |
| 通知中繼綁定（安裝識別碼、公開網域、簽章密鑰）、或想確認／請維護者代為刪除上面任何一項 | 透過 GitHub repo 的 Issues 提出，維護者核對後在伺服器後台刪除（Issue 是公開的，請不要貼出密碼、Cookie 等敏感內容） |

說明：

- 刪除只在**主要伺服器**處理，備用伺服器會在同步時（通常數分鐘內）跟著刪除；主要伺服器暫時連不上時，
  設定頁會請您稍後再試，不會假裝成功。
- **無法刪除的部分**：全域累計數字（總下載次數、各番劇觀看／看完次數）已是彙總值，無法拆回個人；
  錯誤回報不含任何可指向個人的欄位，因此也無法依人刪除；伺服器日誌到期（約 30 天）自動清除。
- 您也可以隨時關閉統計與錯誤回報，停止之後的所有回報。
